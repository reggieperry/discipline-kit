name: Dual-leg implementations diverge at language primitives, not at logic
description: When two languages implement the same computation for independent verification, the divergence risk is in the primitives — line splitting, whitespace classes, regex dialects, rounding modes — not in the algorithm. Pin them at the byte level with shared fixtures and an explicit cross-language PRNG.
type: feedback
volatility: durable
---
When a check is implemented twice in different languages so the legs can verify each other, the algorithm is rarely where they diverge — the primitives are. Line splitting (Scala's `linesIterator` honors the Java terminator set; Python's `splitlines()` honors a larger one including vertical tab and the separator control characters), whitespace classes (Java's default `\s` is ASCII; Python's is Unicode), regex dialects, rounding modes (Java `HALF_UP` versus Python banker's), integer division sign, and sort stability all differ silently between mainstream languages.

**Why:** A two-leg discharge (Scala production summarizer, Python independent recount) was built by one author, self-reviewed for fail-closed paths, determinism, and metric fidelity — and still shipped a HIGH cross-leg divergence in line handling, found only by an adversarial review lens. The author had written both legs and trusted that "both scan whole lines" without checking that the two languages scan them differently. The divergence was fail-closed on the signed number (the receipt is authored by the production-faithful leg and byte-compared, so a wrong count could never sign) but it would have defeated the recount-agreement certification the second leg exists to provide. The cure that landed: a separator fixture pinned in both legs, and the correct golden obtained empirically — write the fixture, run the leg, let it state its own behavior — rather than predicted from documentation.

**How to apply:** Whenever the same computation exists in two languages: (a) enumerate the text-primitive decisions in a shared operationalization note — line terminators, whitespace class, tokenizer, regex dialect, rounding mode, float formatting — at the byte level, not by intent; (b) commit one shared edge fixture (exotic separators, mixed whitespace, boundary numerics) that both legs must reproduce identically; (c) for any stochastic component, share an explicit cross-language PRNG (a hand-implemented splitmix64 stream, never a language's default Random — same seed, different language, different sequence); (d) declare the comparability policy per receipt class before comparing — integer receipts byte-identical, float receipts either a pinned rounding mode in both legs or a stated tolerance; (e) obtain goldens empirically from each leg where behavior is primitive-dependent. Budget one explicit primitives-diff pass in self-review; it is precisely the seam a single author of both legs cannot see by reading. (f) An out-of-band config channel — a value carried in a config field or id marker rather than in the observed party's own output — needs a frame/output-invisibility FIXTURE proving it never reaches what that party reads, not an argument that it doesn't.
