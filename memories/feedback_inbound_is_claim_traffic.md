# Inbound is claim-algebra traffic (adopter machinery; the kit is the first customer)

Everything arriving from outside a repo maps onto the claim algebra. A **bug report** is an attempted refutation of a claim; a **feature request** is an externally authored story; a **foreign PR** is a testimony-grade contribution. This is tier logic, not kit-repo logic — the machinery (the fork-PR guard, the issue templates, the triage doctrine, CONTRIBUTING, the interchange block) ships as adopter machinery, and the kit's own repo adopts it first. On a private, solo, local repo the guard is moot and the Options section says so.

**How to apply:**
- **A bug names its claim.** Identify the contested claim the report attacks; where none exists — the common case for a repo with sparse coverage — the bug names a claim that *should have existed*: register it and its refutation together, so inbound defects grow the claim coverage instead of bypassing it.
- **Reproduce-or-park.** An unreproducible report is testimony with a could-not-run note and a named missing receipt, never a silent close. A reproduced bug files as a proper two-entry refutation crediting the reporter by handle — community-found defects die with honors on the record.
- **Features route to `story-intake`** (a public issue is its second board source), scored on the same rubric, gaps posted back as questions.
- **Foreign PRs land testimony-grade** (`adversarial-review` `foreign-pr` mode); the maintainer wraps the contribution in the claim and the gate signs after merge — no contributor runs the full loop.
- **Signatures never arrive from outside the gate.** A contributor never adds a `"status":"signed"` line; the `inbound-guard` workflow rejects a fork PR that does. See [[verify-claims-not-badges]], [[adversaries-hunt-never-vote]].
